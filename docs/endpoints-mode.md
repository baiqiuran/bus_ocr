# 只提取站点与线路走向

`--extract-mode endpoints` 只识别线路号、首站和末站。当前站名、方位来自图片文件名，不需要 OCR。默认 `full` 保持原来的完整识别流程。

例如 `安平小区-东-01.jpg` 的 6 路输出：

```json
{
  "station": "安平小区",
  "direction": "东",
  "station_key": "安平小区-东",
  "route": "6",
  "first_stop": "金山浦上公交枢纽站",
  "last_stop": "公交仁德站",
  "route_direction": "金山浦上公交枢纽站→公交仁德站"
}
```

`station_key` 标识当前站点的方位，首末站组成有顺序的线路走向。甲→乙和乙→甲分别保留。同一张牌上的多条线路分别输出；拆成多张图片的同一站点按相同 `station_key` 关联，每行保留来源图片及版块编号。

## 字段与身份规则

其他 Agent 的执行步骤见 [Agent 调用约定](agent-guide.md)。本节是字段口径；后文“当前已知问题”记录实现尚未满足口径的情况。

| 字段 | 类型 | 来源与规则 |
| --- | --- | --- |
| `station` | 字符串 | 当前站牌的站名，优先从文件名提取；它不是本条线路的首站或末站 |
| `direction` | 字符串 | 文件名给出的当前站点方位，预期为北、南、东、西；无法确定时保留异常 |
| `station_key` | 字符串 | `station + "-" + direction`，如 `安里-东`；同站同方位不同页、不同线路共用此键 |
| `route` | 字符串 | 线路标识，保留 `K1`、`通学专线13` 等有意义的前缀和限定词；未知时保留空值并复核 |
| `first_stop` | 字符串 | 当前行车方向的首站全称，保留括号附注 |
| `last_stop` | 字符串 | 当前行车方向的末站全称，保留括号附注 |
| `route_direction` | 字符串 | 首末站均有值时为 `first_stop + "→" + last_stop`；任一缺失时为空 |
| `needs_review` | 布尔值 | 待核实候选标记；`false` 也不等于经过人工验证 |
| `poster` | 字符串 | 原图片文件名去掉扩展名，保留正反面/页序来源 |
| `block_index` | 整数 | 当前图片内从 0 开始的线路版块编号；不是站序或全局线路编号 |

支持的常规命名形态：`站名-方位-页号.jpg`、横版的 `站名-方位-线路号-页号.jpg`；如 `安铺村-北，小灯箱80x130CM-01.jpg`，方位段以“北”开头时也可解析。非标准命名需先核对实际解析值；`--station` 只提供兜底站名，不补造方位。

线路走向独立于站点方位：方位为“东”不代表首末站按东西排序，也不能把当前站点的方位赋给沿途每个站。首末站按版面证据和箭头确定，反向分别保留。正反面相同结果仍保留两份图片来源；聚合或去重属于后续显式处理。

票价、首末班、公司、日期、普通中间站以及牌面“下一站”字段不属于当前精简提取范围。

### 不补全途经站点

本任务只提取当前站名、文件名方位、线路号和有序首末站。**不识别、整理或补充完整途经站序，也不通过 AI 常识、外部线路库或搜索结果补造中间站点。**

原图或相邻上下文即使包含中间站，也只用于定位和复核目标端点，不扩展为沿途站点列表。`endpoints` 只保存首站、末站；`stops=[]` 保持未提取完整站序的含义，不把中间站填入其他字段或另行生成完整站表。

完整途经站序属于另行明确的任务范围；本任务持续使用 `endpoints` 模式。

## 运行

在 `E:/BaiduNetdiskDownload/bus_ocr` 内运行，先用少量图片验证：

```powershell
python -m buspipe run "E:/BaiduNetdiskDownload/底板/1-10/安平小区" --out "output/endpoints-sample" --extract-mode endpoints --threads 4
```

整目录运行（会开始实际 OCR）：

```powershell
python -m buspipe run "E:/BaiduNetdiskDownload/底板" --out "output/endpoints" --extract-mode endpoints --threads 4
```

中断后重跑同一命令即可。全量与精简模式使用不同的输出目录、工作目录及 manifest，避免已完成状态跳过新模式、或人工修正的序号混用。尝试混用时会给出错误提示。

旧入口也可指定：

```powershell
$env:BUS_SRC="E:/BaiduNetdiskDownload/底板/1-10/安平小区"
python extract.py --poster 安平小区-东-01 --extract-mode endpoints --out output/endpoints-single.json
```

批处理生成：

- `station_routes.csv` / `station_routes.json`：当前站名、方位、站点键、线路号、有序首末站、来源及 `needs_review`。
- `posters/*_raw.json`：端点坐标、OCR 候选、置信度等，可追溯复核。
- `review/待人工复核.csv`：空文字、低置信度、跨列、线路号不确定等异常。
- `batch_report.json` / `batch_report.md`：模式、耗时、调用数量和失败项。

## 识别与复核规则

本地仍对完整图片做几何定位，但只把线路号和两端站名列送入 OCR。首末站附注按整行列宽和间距分组保留；边缘日期或“执行”说明会跳过，再尝试相邻列。普通中间站、票价、时间、公司等不参与 OCR。

正常线路需要 3 张线路号裁片及 1 张端点画布；发生空结果、跨列或低覆盖时，仍允许端点单列回退。端点之间至少留 100px 白边，减少短站名被检测成一行的情况。

读不清的端点保留为空并进入复核，不用中间站替代。`needs_review=true` 的记录仍是待核实候选。配置 VLM 后只复核异常端点，不调用 VLM 识别整张牌。

原始 JSON 的 `endpoints` 独立于完整站序的 `stops`，不会声称“整条线路只有两站”。人工修正沿用 `override` 命令，但精简模式的 `SEQ=1` 表示首站、`SEQ=2` 表示末站。完整站序的下站比对、双向站序相似度检查在本模式中跳过。

## 横版正反面

同一条 `--extract-mode endpoints` 命令会自动选择竖版或横版模板。已适配样本中的紫底、绿底及黄色招呼站单线路横版，包含正面和反面两种布局；`full` 仍用于原来的完整站序流程。

- 正面：按红色“开往”文字的位置分开裁取首末站。分隔词不送 OCR，因此不会因“开往”读成“开住”而丢失走向。
- 反面：按红色分隔箭头定位站名行，去掉设施小图标及底部说明栏，只识别两端站名和需要确认的相邻括号附注。箭头向左时交换首末站；无法确认箭头时加入复核。
- 两面分别保留来源记录，不按正反面文件序号推断走向。文件名方位仍只用于 `station_key`。
- 文件名中的线路号用作提示，与 OCR 结果冲突或 OCR 不确定时进入复核；`route_ocr` 保存实际识别结果。`地铁接驳6号专线` 统一为 `接驳6`，`K1`、`通学专线13` 保留前缀。
- 端点坐标保留原图位置，人工修正和 VLM 复核继续使用原图裁片。清楚分隔的竖排字会重排识别；不能可靠分字的列保留竖排顺序。

未匹配已知布局的横图会明确报错，不从当前站或下站补造首末站。横版验证记录见 [横版验证](landscape-validation.md)。

| 公园“东部3号线”蓝底白字 | 待适配 | 该特殊版式仍需单独适配，保持复核/失败证据；不能因红框修复就宣称该模板已支持 |

早期诊断使用的 `stop_x1=4000`、`route_end + 1100` 仅为对照实验。正式修复按像素和连续文字段确定范围，没有把这两个临时坐标作为通用配置；验证范围见 [裁切修复验证](crop-fix-validation.md)。

修改任何版面 px 阈值前，按 [模板族阈值修改规则](template-profiles.md) 先固定旧模板基准，再通过 `buspipe/templates.py` 的模板族 profile 做隔离；不要直接改全局默认值。

AI 收到的裁片若只有边框或缺少底部文字，应保留不确定性并定位原图；AI 复核本身不能恢复裁片外未提供的内容。现有复核状态不应通过猜站名或删除限定词来消除。

## 下游：写入外部线路导出表

本模式导出的 `station_routes.csv` 可以继续映射到外部线路导出表的 `途径线路.方位`，但这是独立的导入整理步骤，不是 OCR 提取步骤：

- 先按目标线路的 `上下行 + 停靠序号` 确定走向，再匹配源记录的 `起点/终点`；
- 站点名先完全同名，再做去“站”、括号主名、核心名回退；
- 优先使用不带线路名后缀的整板来源，整板内再优先完全同名；
- 整板仍无法唯一判向时，才使用 XMP 图片最新时间作为最终权重；
- 设施方位 `场站/上客点/下客点` 原样保留，除非导入系统另有明确映射；
- 无法唯一判向、时间相同或没有来源的，留空并保留复核记录。

完整口径、权重顺序、时间字段、溯源链和验证清单见 [导入方位映射规则](direction-mapping.md)。
