# 导入表方位映射规则

本规则用于把 `全量成功数据.xlsx` 中的站点-线路-方位记录，映射到外部线路导出表 `线路导出信息*.xlsx` 的 `途径线路` 表 `方位` 列。它不是 OCR 提取步骤，不重新识别图片，也不补全完整站序。

**核心原则：先按线路走向和整板证据判断，再用图片最新时间加权；没有唯一证据时留空，不猜。**

## 1. 输入与口径

### 1.1 源数据

仅使用 `全量成功数据.xlsx` 的 `可导入记录` 工作表；等价的 CSV 来源是 `output/full-20261023-endpoints/station_routes.csv`。

参与映射的源记录必须同时满足：

- `数据状态 = 可导入`
- `线路名称` 非空
- `站点名称` 非空
- `方位` 非空且不是 `未知`

`空线路号`、`端点待复核`、`方位未知` 不作为方位映射依据。源字段：

| 字段 | 用途 |
| --- | --- |
| `站点名称` | 站点身份 |
| `方位` | 要写入目标表的值 |
| `线路名称` | 线路身份 |
| `起点` / `终点` | 判断线路走向 |
| `起讫点` | 可读的起点→终点 |
| `海报` / `板块序号` | 回溯图片和版面位置 |

### 1.2 目标数据

目标表为 `线路导出信息*.xlsx` 的 `途径线路` 工作表，关键列：

- `线路名称`
- `上下行`
- `停靠序号`
- `途径站点`
- `方位`

目标线路的走向由 `上下行 + 停靠序号` 排序后确定：最小序号是首站，最大序号是末站。不能按行顺序或 Excel 行号推断走向。

## 2. 站点名称匹配

先做 NFKC 归一化、去空白、全半角括号统一，再按以下优先级匹配：

1. **完全同名**：归一化后完全一致。
2. **去尾部“站”**：仅用于找不到完全同名时。
3. **括号前主名**：如 `金港路口站(北侧分站)` 可回退到 `金港路口`。
4. **核心名**：去除括号、`站`、标点和分隔符后的名称。

完全同名优先；括号备注、侧站、上客点/下客点不能无条件合并。若多个来源站落在同一核心名但方向不同，进入第 5 节的冲突处理。

## 3. 用“走向”给源记录标方向

1. 对每条目标线路，分别计算 `上行` 和 `下行` 的 `首站→末站`。
2. 对每个源记录，用源 `起点`、`终点` 与目标上行/下行端点比较。
3. 始发站和终点站各算一次匹配，得到 `0–2` 分：
   - 两端都匹配：优先；
   - 仅一端匹配：可作为弱证据；
   - 两端都不匹配：不能仅凭同名站选方向。
4. 若上行分高于下行分，源记录标记为 `上行`；下行分高则标记为 `下行`；同分且非零标记为 `?`，不自动使用。
5. 源记录必须与目标当前 `上下行` 标签一致，才进入候选。

这说明“走向”优先于“同名站”：同一个站名可以在上下行有两个相反方位，不能用同一条记录同时填两边。

## 4. 整板优先

### 4.1 定义

**整板**指海报文件名不带线路名后缀的站牌记录，例如：

- 整板：`船政路-北-01`、`金融街万达广场-北-01`
- 单线路后缀板：`船政路-南-M5-02`、`鳌峰支路-西-136-01`、`得贵路-上客点-338-01`

判断方法是：把海报 stem 按 `-` 分段；如果某一段等于当前线路名（忽略尾部 `路`，并处理 `地铁接驳N` → `接驳N`），则该海报是带线路名后缀的单线路板；否则按整板处理。

整板可以包含多条线路板块；整板的方向来自整张站牌，不因某个 block 的局部 OCR 改变。

### 4.2 使用顺序

最高分候选（第 3 节）确定后，按以下顺序判定：

- **A. 整板 + 完全同名，且方向唯一**：直接采用。
- **B. 整板候选没有唯一方向**：在整板候选内取最新 XMP 图片时间；若最新时间只对应一个方向，采用。
- **C. 没有任何整板候选**：在当前方向最高分候选中取最新 XMP 图片时间；若唯一，采用。
- **D. 仍无唯一方向**：留空，进入人工复核；不得用同站不同核心名、相反方向的新图或常识补齐。

这条顺序保留了“整板优先”；时间只在同等级候选之间做最终权重，不用一张相反方向的新海报覆盖整板证据。

### 4.3 示例

- `M5 上行 · 船政路`：
  - 整板 `船政路-北-01` → 北
  - 单线路板 `船政路-南-M5-02` → 南
  - 采用整板：**北**
- `M5 下行 · 船政路`：
  - 整板 `船政路-南-01` → 南
  - 单线路板 `船政路-北-M5-02` → 北
  - 采用整板：**南**
- `13 上行 · 金融街万达广场(鳌江路)`：整板中完全同名的是 `金融街万达广场（鳌江路）-东-01`，采用 **东**。
- `13 上行 · 金融街万达广场`：完全同名整板是 `金融街万达广场-北-01`，采用 **北**。
- `306 上行 · 盖山跃进`：两张整板 `东` / `西` 都存在，进入时间权重。
- `338 上行 · 得贵路`：没有无后缀整板，只有带 `338` 后缀的来源，进入时间权重。

## 5. 图片最新时间权重

### 5.1 取时间

优先读取 JPG 的 XMP：

- `xmp:ModifyDate`
- `xmp:CreateDate`
- `xmp:MetadataDate`

取三者中最新的有效时间，转换为北京时间（UTC+08:00）展示。只有在 XMP 全部缺失时，才回退到文件修改时间。

**文件系统的创建/修改时间通常只是下载、复制或解压时间，不能直接当作站牌设计或安装时间。** 典型例子：

- `创新路西-南-172-01.jpg`
- XMP 修改时间：`2026-09-10 09:28:21`
- 文件修改时间：`2026-10-16 14:12:09`

这种情况下采用 XMP 时间。

### 5.2 使用边界

- 只在当前目标方向、当前优先级的候选内比较时间。
- 不使用方向不匹配的新海报覆盖当前方向。
- 最新时间相同且对应多个方向时，不自动选向。
- XMP 时间是设计文件更新时间，不等同于现场站牌更换时间；它是加权依据，不是现实世界时间证明。
- 时间选择必须保留原始 XMP 值、采用时间和时间来源，便于复核。

### 5.3 时间权重示例

- `306 上行 · 盖山跃进`：西侧整板 2026-09-11 晚于东侧 2026-09-09，采用 **西**。
- `333 下行 · 鹤林生态公园`：南侧 2026-07-25 10:37 晚于北侧 10:35，采用 **南**。
- `338 上行 · 得贵路`：最新候选为 `上客点` 2026-01-06，采用 **上客点**。
- `338 下行 · 得贵路`：最新候选为 `下客点` 2026-01-22，采用 **下客点**。
- `通学专线6 上行 · 晋安榕博小学(东区)`：无整板来源，最新候选为 `东` 2025-10-20 20:10，采用 **东**。
- `27 上行 · 警官学院`：当前上行最高分候选内最新为 `东` 2023-09-08；另有一张更晚的西侧海报属于下行方向，不参与上行判向。

## 6. 设施方位

源数据可能包含：

`场站`、`出站`、`进站`、`上客点`、`下客点`、`上客区`、`下客区`、`首末站`、`上车点`、`下车点`、`站台`

这些值按源数据原样写入目标 `方位`，不能无依据地改写成东南西北。

如果导入系统只接受 `东/南/西/北`：

- 先确认 `场站/上客点/下客点` 等业务含义；
- 另建明确的方向映射表；
- 不要把设施方位当成普通方位直接导入；
- 无法确认的留空。

## 7. 文件写入规则

- 原目标文件只读，不覆盖；先复制为新文件。
- 只填写 `途径线路` 的 `方位` 列，保留其他有效单元格。
- 已有非空 `方位` 不覆盖。
- 只有唯一判定才写入；未匹配、方向无法判定、时间冲突均留空。
- 输出文件名建议包含判定规则，例如：
  - `线路导出信息20261026_方位已映射_整板+最新时间.xlsx`
  - `线路导出信息20261026_多方向冲突判定_整板+最新时间.xlsx`

## 8. 可追溯字段

每一条最终判定至少保留：

| 层级 | 字段 |
| --- | --- |
| 目标 | 目标 Excel 行号、线路、上下行、停靠序号、途径站点、目标上下行起止 |
| 源 Excel | 来源序号、来源 Excel 行号 |
| 源 CSV | `station_routes.csv` 行号 |
| 海报 | 海报名称、板块序号、海报路径 |
| 版面 | 线路板块 y 区间、站点行 y 区间 |
| OCR | 首站/末站文本、置信度、目标上行分/下行分 |
| 时间 | XMP 修改/创建/元数据时间、采用时间、时间来源、是否最新 |
| 判定 | 整板标记、完全同名标记、优先级、最终方向、判定规则、备注 |

必须形成完整链路：

```text
目标表途径线路行
→ 全量成功数据.xlsx / 可导入记录 / 序号、Excel 行号
→ station_routes.csv / CSV 行号
→ all_raw.json / poster + block_index + route
→ 海报 JPG
```

## 9. 验证清单

完成映射后至少检查：

- 目标表行数、已填 `方位` 数、留空数；
- 目标线路数、至少填了一个方位的线路数；
- 只修改 `方位` 列，其他有效单元格无变化；
- 所有已填来源都能回查到源行、CSV 行、海报路径；
- 所有候选海报路径存在；
- 整板/后缀/同名/时间规则的实际数量；
- 原始目标文件哈希未变化；
- 多方向冲突、时间冲突和设施方位数量单独列出。

## 11. 已知限制

- 源 OCR 站名和外部线路导出表站名可能只部分相同；括号、侧站、上下客点容易产生别名合并。
- 单线路后缀板可能包含比整板更新的信息，但按“整板优先”规则不会覆盖整板方向；若要改变优先级，需显式修改规则。
- XMP 时间缺失或时间相同的情况仍要人工判断。
- XMP 时间不是现场更换时间；系统只能证明“设计文件更新时间”，不能证明实际站牌安装时间。
- `场站/上客点/下客点` 等设施方位是否可导入，需要导入系统确认。
- 多方向冲突的最终结论仍建议抽查原海报，尤其是同名站、同起讫点但南北两侧都存在的记录。
